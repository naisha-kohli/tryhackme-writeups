# Windows PowerShell

## 1. Introduction to PowerShell

**PowerShell** is a powerful tool developed by Microsoft for **task automation, configuration management, and system administration**.

It combines:

* A **Command-Line Interface (CLI)** for interacting with the operating system.
* A **scripting language** for automating tasks and creating scripts.
* An **object-oriented environment** that can work with complex data and system components.

PowerShell is built on the **.NET platform**, which allows it to interact with many Windows and system components.

---

## 2. What Is a Scripting Language?

A **scripting language** is a programming language used to write a sequence of instructions that can be executed automatically.

Instead of manually performing the same task repeatedly, we can write a script to perform it for us.

For example, instead of manually creating multiple directories, PowerShell can automate the process:

```powershell
New-Item -Path "TestDirectory" -ItemType Directory
```

PowerShell scripts are generally saved with the `.ps1` file extension.

### Uses of scripting in PowerShell

* Automating repetitive tasks
* Managing files and directories
* Managing processes and services
* System administration
* Configuration management
* User and permission management
* Automating security tasks
* Working with APIs and applications

---

## 3. The Power of PowerShell — Objects

One of the most important features of PowerShell is that it is **object-oriented**.

Traditional command-line tools generally work with **text** as output.

PowerShell works with **objects**.

### What Is an Object?

An **object** is a structured piece of data that contains information and functionality.

An object can contain:

* **Properties** — information or characteristics of an object.
* **Methods** — actions that can be performed on an object.

For example, when PowerShell retrieves information about a process, it returns process objects.

A process object can have properties such as:

```text
Name
Id
CPU
WorkingSet
Path
```

We can access these properties directly:

```powershell
(Get-Process).Name
```

PowerShell can also pass these objects from one command to another using the **pipeline**.

```powershell
Get-Process | Where-Object CPU -gt 100
```

Here:

1. `Get-Process` retrieves process objects.
2. `|` passes those objects to the next command.
3. `Where-Object` filters the objects based on their properties.

### Why Are Objects Powerful?

Because PowerShell works with objects, we can easily:

* Filter data
* Sort data
* Select specific properties
* Modify data
* Pass structured information between commands
* Interact with Windows and .NET components

This object-based approach is one of the major differences between PowerShell and traditional text-based command-line tools.

# 5. PowerShell Commands — Cmdlets

PowerShell commands are commonly called **cmdlets** (pronounced "command-lets").

Cmdlets generally follow a:

```text
Verb-Noun
```

naming convention.

For example:

```powershell

```

The naming convention makes commands easier to understand.

For example:

* `Get-Content` → **Get** the **Content**
* `Set-Location` → **Set** the **Location**
* `Get-Command` → **Get** information about **Commands**

# 9. Get-Alias

`Get-Alias` is used to list aliases available in PowerShell.

```powershell

```

## What Is an Alias?

An **alias** is an alternative, usually shorter, name for a command.

For example:

```powershell
dir
```

is an alias for:

```powershell
Get-ChildItem
```

Therefore, these two commands perform the same basic operation:

```powershell
dir
```

```powershell
Get-ChildItem
```

### Finding the Command Behind an Alias

```powershell
Get-Alias dir
```

This shows that `dir` maps to `Get-ChildItem`.

### Common Aliases

| Alias | Actual Cmdlet   | Use                         |
| ----- | --------------- | --------------------------- |
| `dir` | `Get-ChildItem` | Lists files and directories |
| `ls`  | `Get-ChildItem` | Lists files and directories |
| `cd`  | `Set-Location`  | Changes directory           |
| `pwd` | `Get-Location`  | Shows current location      |
| `cat` | `Get-Content`   | Displays file contents      |
| `cp`  | `Copy-Item`     | Copies items                |
| `mv`  | `Move-Item`     | Moves items                 |
| `rm`  | `Remove-Item`   | Removes items               |

> **Best Practice:** Aliases are convenient when working interactively in the terminal, but when writing scripts, it is generally better to use the full cmdlet names. For example, use `Get-ChildItem` instead of `dir`.

# Windows PowerShell

## 20. Piping, Filtering, and Sorting Data

PowerShell becomes especially powerful when commands are combined using the **pipeline**.

---

## 20.1 Piping

**Piping** is a technique used in command-line environments where the output of one command is passed as the input to another command.

In PowerShell, the pipeline is represented by the vertical bar:

```text
|
```

For example:

```powershell
Get-ChildItem | Sort-Object Length
```

Here:

1. `Get-ChildItem` retrieves files and directories.
2. `|` passes the resulting objects to the next command.
3. `Sort-Object Length` sorts those objects based on their `Length` property.

So instead of manually processing the output of `Get-ChildItem`, we can directly send it to another command.

### General Pipeline Structure

```text
Command 1 | Command 2 | Command 3
```

The output of `Command 1` becomes the input of `Command 2`, and the output of `Command 2` becomes the input of `Command 3`.

---

# 21. Sorting Data with Sort-Object

`Sort-Object` is used to sort objects based on one or more properties.

### Example

```powershell
Get-ChildItem | Sort-Object Length
```

This lists the items in the current directory and sorts them by their `Length` property.

By default, sorting is generally performed in **ascending order**.

To sort in descending order:

```powershell
Get-ChildItem | Sort-Object Length -Descending
```

### Command Reference

| Command                   | Use                               | Example                                           |
| ------------------------- | --------------------------------- | ------------------------------------------------- |
| `Sort-Object`             | Sorts objects based on a property | `Get-ChildItem \| Sort-Object Length`             |
| `Sort-Object -Descending` | Sorts objects in descending order | `Get-ChildItem \| Sort-Object Length -Descending` |

---

# 22. Filtering Data with Where-Object

`Where-Object` is used to **filter objects** based on specified conditions.

### Example

```powershell
Get-ChildItem | Where-Object Extension -eq ".txt"
```

Let's break this down:

```text
Get-ChildItem
      ↓
   Objects
      ↓
     |
      ↓
Where-Object Extension -eq ".txt"
      ↓
Only .txt files
```

Here:

* `Get-ChildItem` retrieves files and directories.
* `|` passes those objects to `Where-Object`.
* `Extension` is the property being checked.
* `-eq` means **equals**.
* `".txt"` is the value being compared.

Therefore, the command returns only files whose extension is `.txt`.

### Common Comparison Operators

| Operator   | Meaning                           | Example                 |
| ---------- | --------------------------------- | ----------------------- |
| `-eq`      | Equal to                          | `Name -eq "test.txt"`   |
| `-ne`      | Not equal to                      | `Name -ne "test.txt"`   |
| `-gt`      | Greater than                      | `Length -gt 1000`       |
| `-lt`      | Less than                         | `Length -lt 1000`       |
| `-ge`      | Greater than or equal to          | `Length -ge 1000`       |
| `-le`      | Less than or equal to             | `Length -le 1000`       |
| `-like`    | Matches a wildcard pattern        | `Name -like "*.txt"`    |
| `-notlike` | Does not match a wildcard pattern | `Name -notlike "*.txt"` |

### More Examples

Find files larger than 1 MB:

```powershell
Get-ChildItem | Where-Object Length -gt 1MB
```

Find files whose names contain `report`:

```powershell
Get-ChildItem | Where-Object Name -like "*report*"
```

Find only `.log` files:

```powershell
Get-ChildItem | Where-Object Extension -eq ".log"
```

# 23. Selecting Specific Data with Select-Object

`Select-Object` is used to select specific properties or a specific number of objects from the pipeline.

### Example

```powershell
Get-ChildItem | Select-Object Name, Length
```

Instead of displaying all available properties of the objects returned by `Get-ChildItem`, this command displays only:

* `Name`
* `Length`

### Example Output Concept

```text
Name              Length
----              ------
test.txt          1024
image.jpg         50432
report.pdf        81920
```

### Command Reference

| Command                | Use                         | Example                                       |
| ---------------------- | --------------------------- | --------------------------------------------- |
| `Select-Object`        | Selects specific properties | `Get-ChildItem \| Select-Object Name, Length` |
| `Select-Object -First` | Selects the first objects   | `Get-Process \| Select-Object -First 5`       |
| `Select-Object -Last`  | Selects the last objects    | `Get-Process \| Select-Object -Last 5`        |

### Important Difference

`Where-Object` **filters objects**.

`Select-Object` **selects properties or specific objects**.

For example:

```powershell
Get-ChildItem | Where-Object Extension -eq ".txt"
```

means:

> Give me only `.txt` files.

While:

```powershell
Get-ChildItem | Select-Object Name, Length
```

means:

> Show me only the `Name` and `Length` properties.

---

# 24. Combining Filtering, Sorting, and Selecting

PowerShell allows multiple commands to be chained together.

For example:

```powershell
Get-ChildItem | Where-Object Extension -eq ".txt" | Sort-Object Length | Select-Object Name, Length
```

This performs several operations:

1. `Get-ChildItem` → Gets files and directories.
2. `Where-Object` → Keeps only `.txt` files.
3. `Sort-Object` → Sorts them by file size.
4. `Select-Object` → Displays only the name and size.

This demonstrates the real power of PowerShell's object-based pipeline.

# 25. Select-String

`Select-String` is used to **search for text or patterns inside files**.

It is similar to the `grep` command commonly used in Linux and Unix systems.

### Basic Syntax

```powershell
Select-String -Path "<file>" -Pattern "<text>"
```

### Example

```powershell
Select-String -Path "example.txt" -Pattern "password"
```

This searches `example.txt` for occurrences of the word `password`.

### Searching Multiple Files

```powershell
Select-String -Path "*.log" -Pattern "error"
```

This searches `.log` files in the current directory for the word `error`.

### Command Reference

| Command                  | Use                                      | Example                                                 |
| ------------------------ | ---------------------------------------- | ------------------------------------------------------- |
| `Select-String`          | Searches for text/patterns in files      | `Select-String -Path "example.txt" -Pattern "password"` |
| `Select-String -Pattern` | Specifies the text/pattern to search for | `Select-String -Path "*.log" -Pattern "error"`          |

### Security Use Case

`Select-String` can be useful during security investigations for searching logs for:

* Error messages
* Authentication events
* Suspicious keywords
* IP addresses
* Usernames
* File paths
* Indicators of compromise (IOCs)

# 33. Get-FileHash

`Get-FileHash` generates a **cryptographic hash** for a file.

A hash is a fixed-length value generated from the contents of a file.

Even a small change to a file will normally result in a different hash.

### Basic Syntax

```powershell
Get-FileHash -Path "<file>"
```

### Example

```powershell
Get-FileHash -Path "example.exe"
```

By default, PowerShell commonly uses the **SHA-256** hashing algorithm.

### Specifying a Hash Algorithm

```powershell
Get-FileHash -Path "example.exe" -Algorithm SHA256
```

Other supported algorithms may include:

```text
SHA1
SHA256
SHA384
SHA512
MD5
```

### Command Reference

| Command                   | Use                                      | Example                                              |
| ------------------------- | ---------------------------------------- | ---------------------------------------------------- |
| `Get-FileHash`            | Generates a cryptographic hash of a file | `Get-FileHash -Path "example.exe"`                   |
| `Get-FileHash -Algorithm` | Specifies the hashing algorithm          | `Get-FileHash -Path "example.exe" -Algorithm SHA256` |

### Security Use Case

File hashes are commonly used to:

* Verify file integrity
* Compare files
* Identify known malicious files
* Verify downloaded files
* Investigate suspicious files
* Share Indicators of Compromise (IOCs)

For example, if a security team has a known malicious SHA-256 hash, you can calculate the hash of a suspicious file and compare the two values.

# 37. Invoke-Command

`Invoke-Command` is used to execute PowerShell commands on **remote systems**.

It is an important cmdlet for remote administration and authorized security testing.

### Basic Syntax

```powershell
Invoke-Command -ComputerName "<computer>" -ScriptBlock { <command> }
```

### Example

```powershell
Invoke-Command -ComputerName "Server01" -ScriptBlock { Get-Process }
```

This asks the remote computer `Server01` to execute:

```powershell
Get-Process
```

### Executing Multiple Commands

```powershell
Invoke-Command -ComputerName "Server01" -ScriptBlock {
    Get-ComputerInfo
    Get-Process
    Get-Service
}
```

### Command Reference

| Command                        | Use                                        | Example                                                                |
| ------------------------------ | ------------------------------------------ | ---------------------------------------------------------------------- |

| `Invoke-Command -ComputerName` | Specifies the remote computer              | `Invoke-Command -ComputerName "Server01" -ScriptBlock { Get-Process }` |

# 39. Combined PowerShell Examples

PowerShell becomes particularly useful when multiple concepts are combined.

### Find large files

```powershell
Get-ChildItem | Where-Object Length -gt 1MB | Sort-Object Length -Descending | Select-Object Name, Length
```

Process:

```text
Get-ChildItem
      ↓
Find files larger than 1 MB
      ↓
Sort by size
      ↓
Display Name and Length
```

### Find running services

```powershell
Get-Service | Where-Object Status -eq "Running" | Select-Object Name, Status
```

### Find listening TCP connections

```powershell
Get-NetTCPConnection | Where-Object State -eq "Listen"
```

### Analyze running processes

```powershell
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 Name, Id, CPU
```

This:

1. Gets running processes.
2. Sorts them by CPU usage.
3. Selects the first 10 processes.
4. Displays their name, PID, and CPU usage.
