# Windows Command Line

## Introduction

> Everyone prefers a GUI until they master a CLI.

There are many reasons why people prefer a **GUI (Graphical User Interface)**.

GUIs are intuitive. If someone offers a GUI interface that you are unfamiliar with, you can quickly explore it and discover how it works by interacting with it. You can poke around and discover the non-trivial parts without necessarily knowing the commands beforehand.

A **CLI (Command-Line Interface)** is more like a prompt where you enter commands. It has a learning curve, but once you master it, it can be more efficient and faster.

## Advantages of Using CLI

| Advantage | Description |
|---|---|
| **Size** | CLI interfaces are generally smaller and simpler than graphical interfaces. |
| **Speed** | CLI can be faster because commands can be executed directly without navigating through graphical menus. |
| **Efficiency** | Once commands are mastered, tasks can often be completed more efficiently. |
| **Low Resource Usage** | CLI requires fewer system resources than GUIs. |
| **Older Hardware** | CLI can run on older hardware systems with limited memory and resources. |
| **Automation** | GUI tasks can be automated by creating batch files or scripts containing the commands that need to be repeated. |
| **Remote Management** | CLI makes it very convenient to manage remote systems such as servers, routers, and IoT devices. |

# Windows Command Line

## PATH

We should note that we can only issue commands within the Windows `PATH`.

The `PATH` environment variable contains the directories where Windows searches for executable commands.

The `set` command can be used to check the environment variables from the command line.

The PATH line is indicated by the line starting with `Path=`.

### Commands

| Command | Usage |
|---|---|
| `set` | Displays environment variables, including the `PATH` variable. |
| `ver` | Determines/displays the Windows operating system version. |
| `systeminfo` | Lists various information about the system, such as operating system information, system details, processor information, and memory information. |
| `systeminfo \| more` | Displays the `systeminfo` output page by page. |
| `Ctrl + C` | Exits/stops the current command or output. |

# Network Troubleshooting

Most of us are used to looking up MS Windows network configuration from the GUI interface, but the Command-Line Interface (CLI) provides many networking-related commands that are useful for troubleshooting.

## `ipconfig`

The `ipconfig` command can be used to check network information.

| Command | Usage |
|---|---|
| `ipconfig` | Displays the IP address, subnet mask, and default gateway. |
| `ipconfig /all` | Displays more detailed information about the network configuration. |

### Network Information

| Term | Meaning |
|---|---|
| **IP Address** | Identifies your device on the network. |
| **Subnet Mask** | Determines which part of the IP address represents the network and which part represents the device. |
| **Default Gateway** | Usually the router that forwards traffic from your network to other networks. |
| **DNS Server** | Translates domain names such as `example.com` into IP addresses. |
| **DHCP** | Automatically assigns network configuration, such as an IP address, to devices. |

`ipconfig /all` provides more information about the network configuration, including the DNS servers and whether DHCP is enabled.

| Command | Example |
|---|---|
| `ipconfig` | `ipconfig` |
| `ipconfig /all` | `ipconfig /all` |

## Network Troubleshooting

One common troubleshooting task is checking if the computer can access a particular server on the internet.

### `ping`

The `ping` command can be used to check whether a particular target can be reached.

| Syntax | Usage |
|---|---|
| `ping target_name` | Checks whether the target is reachable and responds to network requests. |

Example:

`ping example.com`

---

### `tracert`

Another valuable tool for troubleshooting is `tracert`, which stands for **traceroute**.

The `tracert` command traces the network route traversed to reach a target. It inspects the routers along the path and notifies us if they drop a packet because its **Time To Live (TTL)** has reached zero.

| Term | Meaning |
|---|---|
| **TTL (Time To Live)** | Limits how many network hops a packet can make before it is discarded. |

| Syntax | Usage |
|---|---|
| `tracert target_name` | Traces the network route to the target through the routers along the path. |

Example:

`tracert example.com`

---

### `nslookup`

`nslookup` is another useful networking command.

It looks up a host or domain and returns its IP address.

The following command looks up `example.com` using the default name server.

| Syntax | Usage |
|---|---|
| `nslookup target_name` | Looks up a host or domain and returns its IP address using the default name server. |

Example:

`nslookup example.com`

---

### `netstat`

The `netstat` command displays current network connections and listening ports.

| Option | Usage |
|---|---|
| `-h` | Displays the help page. |
| `-a` | Displays all established connections and listening ports. |
| `-p` | Shows the program associated with each listening port and established connection. |
| `-o` | Reveals the PID (Process ID) associated with the connection. |
| `-n` | Uses a numerical form of addresses and port numbers. |

### Combining `netstat` Options

We can combine these options and execute the following command:

`netstat -aon`

The command combines:

| Option | Meaning |
|---|---|
| `-a` | Displays all established connections and listening ports. |
| `-o` | Reveals the PID associated with the connection. |
| `-n` | Uses numerical addresses and port numbers. |

The result of `netstat -aon` can be quite long.

# File and Disk Management

## `cd`

The `cd` command can be used to navigate between directories.

Using `cd` without any parameters displays the **current drive and directory**.

| Command | Usage |
|---|---|
| `cd` | Displays the current drive and directory. |
| `cd directory_name` | Changes to the specified directory. |

Example:

`cd`

To change to a particular directory:

`cd directory_name`

---

## `dir`

The `dir` command can be used to view the contents of a directory, including its child directories.

| Command | Usage |
|---|---|
| `dir` | Displays the contents of the current directory. |
| `dir /a` | Displays hidden and system files as well. |
| `dir /s` | Displays files in the current directory and all subdirectories. |

### `dir /a`

The `/a` option displays hidden and system files in addition to the normal files.

`dir /a`

### `dir /s`

The `/s` option displays files in the current directory and all of its subdirectories.

`dir /s`

---

## Changing Directories

You can change to any directory using the `cd` command followed by the directory name.

### Syntax

`cd directory_name`

### Example

`cd Documents`

## `type`

When you are curious about the contents of a particular text file, you can view its contents using the `type` command.

### Syntax

`type filename`

| Command | Usage |
|---|---|

| `type filename \| more` | Displays a long text file page by page. |

# Task and Process Management

The `tasklist` command can be used to list the processes currently running on the system.

| Command | Usage |
|---|---|
| `tasklist` | Lists the currently running processes. |

### Example

`tasklist`

---

## Filtering `tasklist`

We can use a filter with `tasklist` when we want to search for a specific process.

For example, to search for a task related to `sshd.exe`:

`tasklist /FI "ImageName eq sshd.exe"`

The `/FI` option is used to **set a filter**.

In this example:

| Part | Meaning |
|---|---|
| `/FI` | Sets a filter for the `tasklist` command. |
| `ImageName` | Specifies that the filter should be applied to the process image name. |
| `eq` | Means **equals**. |
| `sshd.exe` | The process name being searched for. |

Therefore:

`tasklist /FI "ImageName eq sshd.exe"`

searches the running processes and displays processes whose **ImageName equals `sshd.exe`**.
