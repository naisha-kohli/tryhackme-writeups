# Active Directory — Windows Domain

## What is a Windows Domain?

Imagine you own a small company with only **5–10 computers**.

At first, managing the computers is easy:
- Create user accounts manually on each computer.
- Set passwords individually.
- Install software on every PC.
- Configure settings for each employee separately.

This works for a small business.

However, as the company grows to **100, 500, or even thousands of computers**, managing every computer individually becomes impossible.

To solve this problem, organizations use a **Windows Domain**.

> **Windows Domain:** A group of users and computers managed centrally by an organization.

The main purpose of a Windows Domain is to **centralize the administration** of users, computers, and security settings.

---

# Active Directory (AD)

The central repository used to manage a Windows Domain is called **Active Directory (AD)**.

Active Directory stores information about:
- Users
- Computers
- Groups
- Printers
- Shared folders
- Security policies
- Other network resources

Instead of configuring every computer separately, administrators manage everything from one central location.

> **Definition:** Active Directory is Microsoft's directory service that centralizes the management of users, computers, and other resources within a Windows Domain.

---

# Domain Controller (DC)

The server that runs **Active Directory** is called the **Domain Controller (DC).**

A Domain Controller:
- Stores the Active Directory database.
- Authenticates users during login.
- Authorizes access to resources.
- Applies security policies.
- Manages all devices in the domain.

### A Domain Controller may also provide services like:
- Database Server
- File Server
- Authentication Server
- DNS Server
- Workstation Management

> Think of the **Domain Controller as the "brain" of the Windows Domain.**

---

# Advantages of Using a Windows Domain

## 1. Centralized Identity Management

Administrators can create and manage user accounts from one place.

Instead of creating the same user on multiple computers:

- Create the user once in Active Directory.
- The user can log in from any domain-joined computer (if permitted).
- Password changes happen only once.
- User permissions are managed centrally.

---

## 2. Centralized Security Policies

Administrators can configure security settings once and apply them across the entire organization.

Examples:
- Password complexity requirements
- Password expiration
- Screen lock timeout
- USB restrictions
- Software installation policies
- Firewall settings

Changes made in Active Directory automatically apply to users and computers in the domain.

---

# Real-World Example

Imagine a company called **ABC Technologies** with **300 employees**.

Without a Windows Domain:
- IT staff must visit every computer individually.
- Create user accounts manually.
- Reset passwords separately.
- Install software one PC at a time.
- Update security settings on every computer.

This would be slow, repetitive, and difficult to manage.

With a Windows Domain:
- All employee accounts are stored in **Active Directory**.
- One **Domain Controller** manages the entire network.
- Employees can log in using the same domain account.
- Password resets happen from one place.
- Security policies are applied automatically to every computer.

This saves time, improves security, and makes administration much easier.

# Active Directory Domain Services (AD DS)

## What is Active Directory Domain Services (AD DS)?

**Active Directory Domain Services (AD DS)** is the core service of Active Directory.

It acts as a **central catalog (database)** that stores information about every object in the Windows Domain.

These objects include:
- Users
- Computers
- Groups
- Printers
- Shared folders
- Services
- Organizational Units (OUs)

> **Definition:** AD DS is a centralized directory service that stores and manages all objects within a Windows Domain.

---

# Active Directory Objects

Objects are the resources stored and managed inside Active Directory.

## 1. Users

Users are one of the most common objects in Active Directory.

A user object represents:
- An employee
- An administrator
- A service account

Each user has attributes such as:
- Username
- Password
- Email
- Group membership
- Permissions

---

## 2. Machines (Computers)

Computers joined to the domain are also stored as objects in Active Directory.

Each domain-joined computer has its own account.

Computer accounts usually end with a **`$`**.

Example:

```
DESKTOP-01$
```

The **`$`** indicates that the object is a **computer account**, not a user account.

---

## 3. Security Groups

A **Security Group** is a collection of users or computers that share the same permissions.

Instead of assigning permissions individually to every user, administrators assign permissions to the group.

When a new user is added to the group, they automatically inherit the group's permissions.

### Example

Instead of giving **50 employees** access to a shared folder one by one:

- Create a group called **HR Team**
- Grant the group permission to access the folder
- Add employees to the group

Every member automatically receives the required permissions.

---

# Default Security Groups

## Domain Admins
**Description:** Have full administrative privileges across the entire domain, including Domain Controllers.

---

## Server Operators
**Description:** Can administer Domain Controllers but cannot modify administrative group memberships.

---

## Backup Operators
**Description:** Can access all files regardless of permissions to perform backups and restores.

---

## Account Operators
**Description:** Can create, modify, and manage user and group accounts (excluding administrative accounts).

---

## Domain Users
**Description:** Contains all standard user accounts in the domain by default.

---

## Domain Computers
**Description:** Contains all computers that have joined the domain.

---

## Domain Controllers
**Description:** Contains all Domain Controllers in the domain.

---

# Active Directory Users and Computers (ADUC)

**Active Directory Users and Computers (ADUC)** is a Windows administrative tool used to manage Active Directory.

Using ADUC, administrators can:
- Create users
- Delete users
- Modify user accounts
- Create groups
- Manage Organizational Units (OUs)
- Manage computers
- Reset passwords
- Move objects between Organizational Units

> ADUC provides a graphical interface for managing Active Directory objects.

---

# Default Containers and Organizational Units

## Built-in
Contains the default administrative groups available in every Windows domain.

---

## Computers
Stores newly joined domain computers by default.

---

## Domain Controllers
Default Organizational Unit (OU) that contains all Domain Controllers in the domain.

---

## Users
Contains default user accounts and default security groups for the domain.

---

## Managed Service Accounts
Stores service accounts used by applications and Windows services.

# Organizational Units (OUs)

An **Organizational Unit (OU)** is a container used to organize users, groups, and computers inside Active Directory.

OUs help administrators:
- Organize objects logically
- Delegate administration
- Apply Group Policies (GPOs)

Example:

```
Company
│
├── HR
├── Finance
├── IT
└── Sales
```

Each department can have its own users, computers, and policies.

---

# Security Groups vs Organizational Units (OUs)

| Security Groups | Organizational Units (OUs) |
|-----------------|----------------------------|
| Used to assign permissions to resources. | Used to organize Active Directory objects. |
| Grant access to files, folders, printers, and network resources. | Used mainly for applying Group Policies (GPOs) and administrative delegation. |
| Users inherit permissions when added to the group. | Objects inherit policies based on the OU they belong to. |

### Example

**Security Group**
- Allow members of the **HR Team** to access a shared folder.
- Allow members of **IT Support** to use a network printer.

**Organizational Unit**
- Apply a stricter password policy to the **Finance** department.
- Disable USB storage for computers in the **Sales** department.
- Deploy software only to users in the **IT** department.

---# Managing Organizational Units (OUs)

## Deleting an Organizational Unit (OU)

Sometimes an Organizational Unit (OU) cannot be deleted even if you have the required permissions.

This usually happens because the OU is protected from accidental deletion.

### Example

Suppose your company has gone through a **budget cut**, and the **Marketing** department no longer exists.

You need to delete the **Marketing OU**, but Windows prevents you from deleting it.

### To delete the OU:

1. Open **Active Directory Users and Computers (ADUC)**.
2. Click **View → Advanced Features**.
3. Right-click the Organizational Unit (OU) and select **Properties**.
4. Open the **Object** tab.
5. Uncheck **Protect object from accidental deletion**.
6. Click **Apply** → **OK**.
7. Delete the Organizational Unit.

> **Note:** By default, many Organizational Units are protected to prevent administrators from accidentally deleting important objects.

---

# Delegation of Control

**Delegation** allows Domain Administrators to give specific users permission to perform certain administrative tasks **without giving them full Domain Admin privileges**.

This follows the **Principle of Least Privilege**, where users receive only the permissions they need.

### Example

An **IT Support** employee may need to:
- Reset employee passwords
- Unlock user accounts
- Create new users

Instead of making them a **Domain Administrator**, we can delegate only those specific tasks.

---

## Steps to Delegate Control

1. Right-click the Organizational Unit (OU).
2. Select **Delegate Control...**
3. Click **Next**.
4. Add the user or group that should receive the permissions.
5. Click **Next**.
6. Choose the common task(s) to delegate (e.g., **Reset user passwords and force password change at next logon**).
7. Click **Next**.
8. Click **Finish**.

> Delegation provides limited administrative privileges, making the environment more secure.

# Resetting a User Password Using PowerShell

In this example, **Phillip** logs into his computer and resets **Sophie's** password using **Windows PowerShell**.

## Step 1 – Reset Sophie's Password

Run the following command:

```powershell
Set-ADAccountPassword sophie -Reset -NewPassword (Read-Host -AsSecureString -Prompt 'New Password') -Verbose
```

### What it does

- `Set-ADAccountPassword` → Resets an Active Directory user's password.
- `sophie` → The target user account.
- `-Reset` → Forces a password reset.
- `Read-Host -AsSecureString` → Prompts the administrator to enter the new password securely.
- `-Verbose` → Displays detailed information about the operation.

---

## Step 2 – Force Password Change at Next Login

After resetting the password, force Sophie to choose a new password when she logs in.

Run:

```powershell
Set-ADUser -ChangePasswordAtLogon $true -Identity sophie -Verbose
```

### What it does

- `Set-ADUser` → Modifies an Active Directory user.
- `-ChangePasswordAtLogon $true` → Forces the user to change their password at the next login.
- `-Identity sophie` → Specifies the target user.
- `-Verbose` → Displays detailed information.

> After these commands are executed by **Phillip**, **Sophie** can log in using the temporary password and will immediately be prompted to create a new one.

# Managing Computers in Active Directory

## Organizing Computers

By default, when a computer joins a Windows Domain, it is placed inside the **Computers** container.

However, it is considered good practice to organize computers into different **Organizational Units (OUs)** based on their purpose.

### Example Structure

```
Company
│
├── Workstations
│   ├── LPT-01
│   ├── LPT-02
│   ├── PC-01
│   └── PC-02
│
└── Servers
    ├── SRV-DC01
    ├── SRV-FILE01
    └── SRV-WEB01
```

- **LPT** → Laptop
- **PC** → Desktop Computer
- **SRV** → Server

Moving computers into dedicated OUs makes it easier to:
- Apply different security policies.
- Deploy software selectively.
- Restrict user actions.
- Manage updates separately.

For example:
- Workstations may allow users to log in normally.
- Servers require stricter security settings and are managed only by administrators.

---

# Group Policy Objects (GPOs)

A **Group Policy Object (GPO)** is a collection of settings that can be applied to users or computers in an Active Directory domain.

Instead of configuring every computer individually, administrators configure a GPO once, and it automatically applies to all targeted users or computers.

> **Definition:** A Group Policy Object (GPO) is a centralized collection of settings used to manage the configuration and security of users and computers.

---

# How GPOs Work

1. Create a GPO.
2. Configure the required settings.
3. Link the GPO to an Organizational Unit (OU), domain, or site.
4. Every user or computer inside that OU automatically receives the configured settings.

---

# Important Parts of Group Policy Management

## Group Policy Objects

This is where all GPOs are created and stored.

Example:
- Password Policy
- USB Restriction Policy
- Screen Lock Policy

---

## Linked Organizational Units (OU)

A GPO only affects the Organizational Unit (OU) to which it is linked.

Example:

```
Sales OU
    │
    └── Password Policy GPO
```

Only users and computers inside the **Sales OU** receive that policy.

---

## Security Filtering

Security Filtering controls **which users or groups** the GPO applies to.

Example:
- Apply a GPO only to **HR employees**.
- Exclude Domain Administrators from a policy.

---

## Settings Tab

The **Settings** tab displays all configurations contained within a GPO.

Examples:
- Password Policy
- Firewall Rules
- Desktop Restrictions
- Software Installation
- Windows Updates

---

# Editing a Password Policy

Suppose the company wants every employee to use passwords that are **at least 10 characters long**.

### Steps

1. Open **Group Policy Management**.
2. Right-click the required GPO.
3. Click **Edit**.
4. Navigate to:

```
Computer Configuration
    └── Policies
        └── Windows Settings
            └── Security Settings
                └── Account Policies
                    └── Password Policy
```

5. Open **Minimum Password Length**.
6. Set the value to **10 characters**.
7. Click **OK**.

Once the policy updates, every user in the targeted OU must use passwords with at least **10 characters**.

# GPO Distribution (SYSVOL)

All Group Policy Objects are distributed through a shared folder called **SYSVOL**.

SYSVOL is stored on the **Domain Controller (DC)**.

Whenever a computer starts or a user logs in:
1. The computer contacts the Domain Controller.
2. It accesses the **SYSVOL** share.
3. It downloads the latest Group Policies.
4. The policies are applied automatically.

> **SYSVOL** is the shared folder on the Domain Controller that stores Group Policies and other files required by Active Directory.

# Authentication Methods

In a Windows Domain, user credentials are stored on the **Domain Controller**.

Whenever a user tries to access a network resource:
- File Server
- Printer
- Email
- Shared Folder

the service asks the **Domain Controller** to verify the user's identity.

Windows mainly supports two authentication protocols:

- **Kerberos**
- **NetNTLM (NTLM)**

---

# Kerberos Authentication

Kerberos is the **default authentication protocol** used by modern versions of Windows.

Instead of sending passwords over the network, Kerberos uses **tickets**.

### How Kerberos Works

1. User enters username and password.
2. The Domain Controller verifies the credentials.
3. The Domain Controller issues a **Ticket Granting Ticket (TGT)**.
4. The user requests access to a service (e.g., a file server).
5. The Domain Controller issues a **Service Ticket**.
6. The service validates the ticket and grants access.

### Advantages

- Passwords are never repeatedly transmitted.
- Faster authentication after login.
- Mutual authentication (both user and server verify each other).
- More secure than NTLM.

### Example

Rahul logs into his office laptop.

Later, he opens the company file server.

Instead of asking Rahul to enter his password again, Kerberos uses the ticket already issued by the Domain Controller to authenticate him automatically.

---

# NetNTLM (NTLM)

**NTLM (New Technology LAN Manager)** is the legacy authentication protocol used before Kerberos.

It is still used for:
- Older Windows systems
- Workgroup environments
- Applications that do not support Kerberos

Instead of tickets, NTLM uses a **challenge-response** mechanism.

### How NTLM Works

1. User enters username and password.
2. The server sends a random challenge.
3. The client encrypts the challenge using information derived from the user's password hash.
4. The server verifies the response.
5. Access is granted if the response is correct.

### Disadvantages

- Less secure than Kerberos.
- Slower authentication.
- More vulnerable to attacks such as Pass-the-Hash.

---

# Kerberos vs NTLM

| Kerberos | NTLM |
|-----------|------|
| Modern authentication protocol | Legacy authentication protocol |
| Uses tickets | Uses challenge-response |
| Faster | Slower |
| More secure | Less secure |
| Default in Active Directory | Used mainly for backward compatibility |

# Trees, Forests, and Trusts

As organizations grow, a single domain may no longer be sufficient.

Active Directory allows companies to expand using **Trees**, **Forests**, and **Trust Relationships**.

---

# Tree

A **Tree** is a collection of multiple domains that share a common namespace.

### Example

Suppose **ABC Technologies** is headquartered in **India**.

Later, it opens a branch in **Germany**.

Instead of keeping everything in one domain, the company creates a child domain.

```
abc.com
│
├── india.abc.com
│
└── germany.abc.com
```

Both domains:
- Share the same namespace (**abc.com**).
- Have separate administrators if needed.
- Can still communicate with one another.

This collection of related domains forms an **Active Directory Tree**.

---

# Forest

A **Forest** is a collection of one or more Trees that may have completely different namespaces.

### Example

ABC Technologies acquires another company called **XYZ Solutions**.

Before acquisition:

```
abc.com

xyz.com
```

Instead of replacing XYZ's infrastructure, both companies keep their own domains.

```
Forest
│
├── abc.com
│
└── xyz.com
```

Both domains:
- Keep separate names.
- Maintain separate Active Directories.
- Share resources securely inside the same forest.

A Forest is the highest-level logical structure in Active Directory.

---

# Trust Relationships

A **Trust Relationship** allows users in one domain to access resources in another domain.

Without a trust:
- Users from one domain cannot access another domain's resources.

With a trust:
- Authentication requests are accepted between domains.

### Example

ABC India stores engineering documents.

ABC Germany needs access to those documents.

Instead of creating duplicate accounts, the administrator establishes a **Trust Relationship**.

Now:
- Employees log in using their own domain accounts.
- They can securely access resources from the other domain (subject to permissions).

> A trust does **not** automatically grant permissions; it only allows authentication between domains. Access still depends on assigned permissions.
